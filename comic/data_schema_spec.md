# Data Layer Schemas

This document defines the strict JSON data structures used across the entire comic generation pipeline. Because the architecture relies on multiple agents and MCP tools handling different parts of the process, adhering to these schemas is critical to prevent hallucinations and data loss during handoffs.

## 1. The Continuity Vault Schemas
These files reside permanently in the local `/vault/` and are queried by the Orchestrator during Phase 2.

### Character Schema (`/vault/characters/{name}.json`)
Defines a character's physical traits and absolute paths to their IP-Adapter anchors.
```json
{
  "entity_id": "warrior_01",
  "type": "character",
  "name": "The Warrior",
  "physical_description": "A rugged man in his 30s with a prominent facial scar over his left eye, wearing asymmetrical dark leather armor and a ragged red cape.",
  "core_tags": "male, scarred, leather armor, red cape",
  "assets": {
    "face_anchor": "/vault/characters/warrior_01_face.jpg",
    "body_anchor": "/vault/characters/warrior_01_body.jpg"
  }
}
```

### Location Schema (`/vault/locations/{name}.json`)
Defines an environment's aesthetic vibe and optional geometric anchor.
```json
{
  "entity_id": "tavern_interior",
  "type": "location",
  "name": "The Broken Keg Tavern",
  "environmental_description": "A dim, smoky medieval tavern made of rotting wood, illuminated by green glowing candles, with scattered wooden tables.",
  "assets": {
    "vibe_anchor": "/vault/locations/tavern_interior_vibe.jpg",
    "depth_map": "/vault/locations/tavern_interior_depth.png" 
  }
}
```

## 2. The Pipeline Handoff Schemas
These files are generated dynamically during the comic creation process.

### Phase 1 Output: `beats.json`
Generated by the Writer agent. It breaks the raw chapter into scenes, isolating the visual actions and defining the "Cast" (which entities must be loaded from the Vault).
```json
{
  "chapter_id": "ch_05",
  "scenes": [
    {
      "scene_id": "s_01",
      "location_id": "tavern_interior",
      "active_characters": ["warrior_01", "tavern_keeper_temp"],
      "beats": [
        "The Warrior slams a gold coin onto the wooden table.",
        "The Tavern Keeper looks nervously at the coin.",
        "The Warrior draws his sword."
      ]
    }
  ]
}
```

### Phase 2 Output: `panels.json`
Generated by the Storyboarder agent. This is the ultimate machine-readable payload that is fed into the ComfyUI MCP tool. Notice how the `physical_description` and `environmental_description` from the Vault schemas are directly injected into the `sdxl_prompt` (enforcing the Echo Rule).
```json
{
  "chapter_id": "ch_05",
  "pages": [
    {
      "page_id": "page_01",
      "layout_type": "3_panel_strip",
      "panels": [
        {
          "panel_id": "p_01",
          "sdxl_prompt": "comic book style, (A dim, smoky medieval tavern made of rotting wood, illuminated by green glowing candles:1.1), (A rugged man in his 30s with a prominent facial scar, wearing dark leather armor:1.2) slamming a gold coin onto a wooden table. Cinematic angle.",
          "negative_prompt": "photorealistic, 3d render, messy lines, text, speech bubbles",
          "ip_adapter_nodes": [
            {
              "entity_id": "warrior_01",
              "image_path": "/vault/characters/warrior_01_body.jpg",
              "weight": 0.85
            }
          ],
          "controlnet_nodes": [
            {
              "type": "depth",
              "image_path": "/vault/locations/tavern_interior_depth.png",
              "weight": 0.6
            }
          ]
        }
      ]
    }
  ]
}
```

## 3. Extended Dialogue Schema

The `dialogue` array in each panel entry supports the following types, covering all text overlay needs of the pipeline:

```json
{
  "panel_id": "p_01",
  "dialogue": [
    {
      "speaker": "warrior_01",
      "text": "Take the gold.",
      "type": "speech"
    },
    {
      "speaker": "narrator",
      "text": "The tavern fell silent. Every eye turned to the coin.",
      "type": "narration"
    },
    {
      "speaker": "warrior_01",
      "text": "Why won't they listen...",
      "type": "thought"
    },
    {
      "speaker": null,
      "text": "CRASH",
      "type": "sfx"
    },
    {
      "speaker": "aymeric_bator",
      "text": "Hey Gus - État des Finances.",
      "type": "im",
      "im_sender": "Aymeric",
      "im_recipient": "Gus"
    }
  ]
}
```

### Dialogue Type Reference

| Type | Visual Rendering | Tail/Pointer | CSS Class |
|---|---|---|---|
| `speech` | White rounded bubble with black border | Pointed tail toward speaker's face | `.bubble-speech` |
| `thought` | Cloud-shaped bubble, dotted border | Circular "thought dots" toward speaker | `.bubble-thought` |
| `shout` | Jagged/spiky bubble, bold text | Pointed tail, larger | `.bubble-shout` |
| `narration` | Rectangular box, semi-transparent dark background | No tail — anchored to panel edge (top or bottom) | `.bubble-narration` |
| `sfx` | Large stylized text, no bubble | No tail — positioned at action point | `.sfx-text` |
| `im` | Styled as in-app IM window (rounded corners, sender name header) | No tail — floating in AR space | `.bubble-im` |
| `whisper` | Small bubble, thin border, italicized text | Small tail, close to mouth | `.bubble-whisper` |

### The `im` Type
This book features extensive in-world Instant Messaging via AR overlays. IM messages are rendered differently from speech bubbles — they appear as floating holographic windows in the panel, styled with the sender's name, a colored header, and monospace text. The `im_sender` and `im_recipient` fields allow the Webtoon CSS to style sender/receiver differently (e.g., outgoing messages right-aligned, incoming left-aligned).
